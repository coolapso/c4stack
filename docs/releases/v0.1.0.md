# C4Stack v0.1.0

The first release of C4Stack: building blocks for Go web apps on Gin, Templ, HTMX and
PostgreSQL, and a generator for new apps. C4Stack is open source under the Apache
License 2.0.

## Requirements

- Go 1.26 or later
- Task 3.53.1 or later
- Docker, for the local and test databases
- PostgreSQL 13 or later in production
- A Hanko tenant; for credits, a Creem store; for credit expiry, Scaleway Transactional
  Email

## Features

**Core**
- `web`: a Gin engine with request IDs, request logs that leave out queries and bodies,
  panic recovery that logs no secrets, a host check, security headers, an extensible
  Content Security Policy, body limits, signed CSRF tokens with an Origin check, and
  sealed cookies.
- Graceful serving with health endpoints: readiness fails first on shutdown, in-flight
  requests drain, and readiness reports a schema older than the binary.
- `app`: the command entry point with `serve`, `migrate`, `migrate status`, `version`,
  `help` and the commands modules and the app register. `migrate` needs only the
  database URL.
- PostgreSQL through `database/sql` with verified TLS by default, and namespaced
  migrations that tolerate newer schemas during rolling upgrades. Module migrations
  adopt tables an app created before it used C4Stack, and `migrate` converts a
  migration history recorded without namespaces.
- `ui`: a default design without a build step, light and dark, usable unchanged,
  restyled through design tokens, or replaced by the app's own layout. Content-hashed
  assets that keep working across rolling deploys.

**Identity and accounts**
- `identity` and `identity/hanko`: Hanko sign-in, session validation on every request,
  sign-out, and profile management for email addresses, passkeys and signed-in devices.
- `accounts`: sign-ins found by provider and subject, with new identities joining the
  account that has their verified email, so users keep their accounts across providers;
  sign-in middleware with CSRF that turns away unverified addresses; settings and
  deletion pages at paths the app can change, each replaceable; and account deletion
  that deletes at the provider first, then, only once the provider confirms, the local
  data in one transaction that modules and the app join. A process without
  sign-in, such as an API gateway, can use the module without a provider.

**Optional modules**
- `apikeys`: API keys with a configurable prefix, stored as hashes, shown once, with
  bearer authentication, a check inside credit transactions, and a keys page to create,
  rename, revoke and delete them.
- `payments` and `payments/creem`: hosted checkout at a server-computed price, and
  verified webhooks.
- `credits`: prepaid credit in EUR cents with an append-only ledger, idempotent charges
  and adjustments, holds for work in progress and their capture, purchases with
  app-chosen limits and fees, webhook processing that sends anything ambiguous to
  review, paged history, a credits page that follows a purchase after checkout, and
  operator commands. Purchases can be turned off.
- `credits/expiry`: expiry of unused credit, only after the email provider reports the
  warning delivered, a full notice period from delivery, and never before the date the
  warning announced.

The modules' tables are Searchbase Cloud's, so Searchbase moves onto this release with
one ordinary release of its own, without moving data. A test in this repository moves
its database and checks that sign-ins, keys, balances, purchases and expiry warnings
carry over.
- `email` and `email/scaleway`: transactional email through Scaleway, with delivery
  reports.

**Generator and tasks**
- `c4stack new` creates an app that pins this release: a short `main.go`, configuration
  with the app's own environment prefix, a layout starting from the default design,
  a local database, a Containerfile, and an AGENTS.md.
- A shared Taskfile that apps include at the same release: development with live reload,
  local and disposable test databases, migrations, tests, checks, builds, container
  images, and `framework:update`.

## Upgrading

This is the first release; there is nothing to upgrade from.
